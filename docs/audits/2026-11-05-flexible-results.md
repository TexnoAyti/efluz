# Flexible text and screenshot result intake

The reported Jasurbek_060 / pesser280101 pair was verified read-only in production: both players exist and their round-2 fixture is unfinished. No live result or proposal was written during diagnosis.

Result intake now separates verified glued usernames, normalizes Unicode score punctuation/keycaps, reads scores adjacent to words, deduplicates repeated player mentions, tolerates ordinary result chatter, and excludes labelled clock times/ISO dates from score candidates. Multiple unlabelled scores, unknown named opponents, invalid scores and inconsistent winner declarations still require clarification. A username plus win/won/yutdi/g‘olib identifies an assertion of victory; it never invents 3:0. A no-score assertion opens a durable same-user/topic missing-score question. The question and stored continuation use the same canonical player order and selected round; its numeric reply enters the existing proposal/approval path.

Allowed result topics now use the structured image extractor for registered nonsuspended accounts, with quota admission, a hard image deadline, four-MB limit and JPEG/PNG signature checks. JPEG/PNG Telegram documents are supported alongside photos, including in the existing owner DM reader. Image input is memory-only and Telegram-file-ID-only. Main score, extra time and shootouts remain distinct; UZEFLIFE uses the cumulative final score where its schema has no extra-time field. Missing optional image metadata defaults to null, while unreadable teams/main score or malformed output do not create a score. The image order is authoritative for scoreless captions; unmapped image-to-username sides prompt clarification. Conflicting captions and images are not silently reconciled.

Source edits invalidate an earlier Telegram proposal before image analysis, and repeated published sources do not invoke OCR again. Existing participant/owner permission, topic, stage, opponent/admin confirmation, fresh fixture fingerprint, source/edit/replay and atomic write safeguards remain in place. Failed OCR can still use a clear textual score caption. Image extraction alone does not finalize a result.

Validation: TypeScript, production build/self-check, existing UZEFLIFE topic/webhook, domestic topic, durable follow-up, German cup, natural-admin and AI enhancement suites. A new regression covers the exact reported usernames/win, repeated/glued names, noisy scores, date/time exclusion, winner conflicts, missing-score continuation, image/document proposals, reversed captions, unknown image identities, source dedupe, forwarded denial and unreadable images. Telegram and model responses are mocked in tests; actual provider OCR accuracy remains dependent on the submitted screenshot.
