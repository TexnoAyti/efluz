# Expanded primary-owner daily digest

The existing 08:00 Asia/Tashkent report only listed four EFL fixture categories. The digest now opens with actionable priorities, then shows a rolling (from,to] 24-hour EFL result/goal summary, per-league round progress, postponed games, known round/individual deadlines, UZEFLIFE round/results/account-link coverage, active TEAMS and El-Clasico results, Telegram recipient delivery receipts and unresolved unknowns, channel publication progress, user growth, and Telegram-confirmed Premium payments in Stars. Unknown delivery from older days remains visible. Expired channel send leases require inspection instead of being described as ongoing sends.

The time window is printed in Tashkent time. Future/hidden/inactive competition work is excluded from the active backlog, individual fixture deadlines override round deadlines, duplicate fixtures are deduplicated, and financial currencies are not mixed. No manual payment totals are inferred from Stars. Private payment charge IDs and user records are not included in the text. A Mini App button opens EFLUZ for follow-up.

Supplementary reads are bounded, read-only, isolated per source, and never initialize tournament state or drain queues. Missing/oversized/timed-out sources are named instead of treated as zero. A shared report deadline bounds ignored-abort reads. Text preserves whole sections and the coverage warnings within Telegram's limit. The existing primary-owner-only preview, enabled setting, local-day delivery claim and no-replay behavior after uncertain delivery remain in place. Preparation, claim and receipt phases now receive independent state deadlines so a slow report cannot exhaust the receipt write deadline.

Validation: TypeScript, production build/self-check, existing AI enhancement/daily-delivery regression, and a new daily digest regression cover time boundaries, money/receipt accuracy, open-round scope, old UZEFLIFE games, per-source outages and limits, malformed pagination, ignored-abort reads, text size and privacy. The new test is included in CI. Telegram calls in tests are mocked; deployment does not resend today's report.
