# Owner tasks in daily reports, the admin panel and Telegram AI

The owner now gets a task digest in the daily report and a task center in Admin → Telegram AI. Thirty-four registered task kinds cover EFL result disputes/reviews, unresolved cup winners, old/due/overdue games, round/matchday deadlines and progression review; UZEFLIFE results, deadlines, postponed games, account linking, next round and completion; TEAMS lineups/results and El-Clasico readiness; unknown/rejected/stalled Telegram deliveries, account contact gaps and missing/stalled/uncertain channel posts; and unavailable/stale source checks.

Tasks are derived from current sources, have stable IDs, severity, reason, next step and location, and disappear on refresh when the underlying issue is resolved. Safe game links are constructed from validated UZEFLIFE/TEAMS identifiers. Reading tasks never changes a result, advances a round, or sends a reminder. A disputed proposal is not offered as an ordinary confirmation, future rounds do not create work, and stale EFL data cannot claim round readiness. Partial sources are disclosed and represented as checks.

The private GET /api/admin/telegram-ai/tasks route validates filters, returns 30 items per page with totals/catalog/coverage, and keeps the original requireAdmin plus primary-owner guards. Daily report payloads expose at most 30 preview tasks; Telegram text highlights five and points to the complete task center. The AI fixed read catalog exposes ai_tasks, and Uzbek requests such as “Bugungi vazifalarimni ko‘rsat” resolve to a read. Delegated AI admins cannot read the owner's cross-platform list. Existing write authorization remains unchanged.

The real API client previously returned a recent cached GET result after a failed refresh even with skipCache. Task/report reads now explicitly disable that fallback so an error cannot present an old task list as newly verified. The task panel handles loading/errors, stale response races, retry, filters and pagination.

Validation: TypeScript, production build/self-check, daily digest, AI enhancement and private read-tool regressions; a new task suite covers derivation, resolution, ordering, scope, source coverage, command parsing, AI owner restrictions, real HTTP ACL/filters and distinct pagination. Browser checks render the actual component and API client at 320/393/844 px with long names, enlarged text, dark theme, filter reset and timeout/retry recovery. Browser and server tests use isolated data and mocked Telegram; no test messages or live results are changed.
