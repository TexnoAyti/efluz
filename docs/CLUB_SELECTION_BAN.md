# Club selection bans

Munfiz accepts `@username ga klub tanlashga ban ber. Sabab: o‘yinlarni o‘ynamadi` and `@username klub tanlash banini olib tashla`. These natural commands use the existing delivered owner confirmation flow. The native planner needs no model quota. An exact username or canonical user ID is required. Only the primary owner may apply or revoke a ban.

`Guruhda yo‘q o‘yinchilarni ko‘rsat` continues to check current active-season club owners against fresh Telegram membership. Each displayed owner gets an individual **Klub tanlashga ban** button, or **Banni olib tashlash** if already banned. Displaying a list changes no ban. Clicking the named button is the owner's explicit action; it does not require another confirmation. It only works in the owner's private bot chat, bound to the delivered message and actual account. Controls expire after one hour, check the current ban revision, and are consumed atomically. Replaying a consumed button cannot restore an old ban after revocation. Refresh the roster to obtain current buttons.

The authoritative `club_selection_bans/{canonicalUserId}` record applies across leagues and seasons until revoked. It is independent of general account suspension, group membership, premium and club ownership. Rejoining a group does not revoke an owner-issued ban. Existing clubs, fixtures, balances and results are retained. Both ordinary claims (including queued/replayed claims) and administrator assignment check the ban in the ownership transaction; a stale session or cached profile cannot bypass it. Bans are not removed by an account profile rewrite. Rejected claims do not change occupancy.

Bans, audit and request receipts commit together. Button operations consume their control in the same transaction as the ban and audit. The service never messages a banned player or removes anyone from a Telegram group. All Telegram tests use mocked transport; no production users are banned by tests.

Validation covers natural grant/revoke and delivered confirmation, owner/delegate isolation, per-owner roster buttons, foreign/undelivered/wrong-message controls, stale revisions, callback webhook dispatch, consumed-button replay after revocation, signed HTTP claims, direct claims and admin assignment against native PostgreSQL, and restoration after revocation.
